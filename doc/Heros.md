这个 Heros 顶部导航并不是传统意义上的“信息型 Navbar”，它更偏向一种**沉浸式世界观入口（World-driven Navigation）**。  
整个设计逻辑明显偏向「视觉氛围优先」，而不是“功能效率优先”。

从版式、字体、留白、状态逻辑，到按钮行为，都在强化一种：

> “用户正在进入某个数字藏馆 / 音乐档案 / 虚拟世界”的感觉。

下面从 UI 架构、视觉层级、字体语言、交互状态、空间逻辑几个层面拆解。


# 一、整体布局结构（Layout Structure）

这个 Hero 顶部采用的是：

## 「横向中心聚焦 + 两侧功能收纳」结构

大致可以抽象为：

```
`\[ Logo \] —— \[ 主导航 \] ————————— \[ 设置 + 登录/注册 \]`
```

但它并不是严格平均分布，而是：

| **区域** | **权重** | **功能** |
| :-: | :-: | :-: |
| 左侧 Logo | 品牌识别 | 世界观入口 |
| 中部 Navigation | 页面切换核心 | 用户当前状态 |
| 右侧 Utility | 功能操作 | 系统行为 |

这种布局有几个明显特点：


## 1. Logo 不贴边

Logo 被刻意向内收缩。

不是：

```
`|Logo`
```

而是：

```
`|    Logo`
```

这会产生：

- 更高级的视觉呼吸感

- 更像品牌网站而不是后台系统

- 避免“工具感”

- 让 Hero 更像封面而不是导航条

这种设计大量出现在：

- 音乐艺术平台

- 时尚品牌

- 游戏世界观官网

- 概念型 Web3 页面


## 2. Navigation 被“居中主导”

中间导航是整个 Hero 的视觉重心。

页面中：

```
`Fresh`

`Design Work`

`Disc Library`

`News Action`

`MSG`
```

它们的间距非常大。

这是故意的。

因为：

### 它不是“菜单”

而是：

## “章节入口（Section Portal）”

每个 Title 更像一个世界入口。

所以：

- 不采用紧凑排列

- 不采用小字体

- 不做传统 hover underline

- 不做顶部小标签

而是：

### 用空间来强化“模块独立性”

即：

```
`每一个导航标题 = 一个独立空间`
```

这是一种很典型的：

# Editorial Layout（编辑式排版）


# 二、字体设计逻辑（Typography System）

这个 Hero 最大的核心之一：

# 字体承担了“状态层级”

不是颜色。


## 1. 当前页面高亮逻辑

例如：

当前停留：

```
`Fresh`
```

那么：

- Fresh = 白色

- 其他 = 灰色

这意味着：

## 当前 Section 被赋予“存在感”

而不是传统：

- 下划线

- 背景块

- Tab 高亮

这种做法更高级。

因为它：

- 不破坏极简氛围

- 不增加视觉噪音

- 保持 Hero 的沉浸感


## 2. 灰色的意义

灰色并不是：

> “不可点击”

而是：

## “当前未聚焦”

这是两个完全不同的设计哲学。

传统后台：

```
`灰色 = disabled`
```

而这里：

```
`灰色 = inactive focus`
```

它仍然可点击。

只是：

- 权重降低

- 注意力降低

- 焦点转移

这是很典型的：

# Ambient UI（环境式 UI）


## 3. 字体大小策略

导航字体明显：

- 偏大

- 偏轻

- 字重不厚

这意味着设计目标不是：

```
`快速阅读`
```

而是：

```
`形成氛围`
```

字体更接近：

- 展览标题

- 音乐分类

- 艺术刊物导航

而不是：

- SaaS 后台

- 电商导航


# 三、Logo 设计与位置关系

Logo 很有特点：

- 金属感

- 荆棘结构

- 高对比锐边

- 黑银色调

这会天然产生：

# “视觉重量”

因此布局上：

## Logo 必须左置

不能居中。

否则：

- 会抢占导航视觉中心

- 导致页面失衡

- Hero 会过于压迫


## Logo 与 Navigation 的距离

Logo 和导航中间留了非常大的空白。

这是非常关键的。

目的：

# 把品牌 与 功能 解耦

即：

```
`Logo = 世界观`

`Navigation = 用户行为`
```

两者不是同一层级。


# 四、顶部 Hero 的空间语言

整个顶部区域非常“宽”。

高度明显高于普通导航栏。

这意味着：

## 它并不只是 Navbar

而是：

# Hero Navigation Layer

即：

- 同时承担氛围

- 品牌展示

- 页面切换

- 空间留白

因此它的高度故意偏大。

这种设计在：

- 音乐类网站

- 概念艺术网站

- 游戏宇宙入口

- AI 艺术平台

特别常见。


# 五、交互状态逻辑（核心）

这是这个 Hero 最重要的部分。


# 当前页面状态逻辑

逻辑可以概括为：

```
`当前所在 section = Active`

`其余 section = Inactive`
```

视觉表现：

| **状态** | **样式** |
| :-: | :-: |
| Active | 白色高亮 |
| Inactive | 半透明灰色 |

当用户切换页面：

例如：

```
`Fresh → Disc Library`
```

则：

```
`Fresh 变灰`

`Disc Library 高亮`
```

本质：

# Navigation 状态与页面路由绑定

即：

```
`activeSection === currentRoute`
```

而不是 hover 临时状态。

这是：

# Persistent State（持久状态）

用户无论：

- 刷新

- 回退

- 深链接进入

顶部都应该正确高亮。


# 六、右侧功能区设计

右侧有三个东西：

```
`⚙ 设置`

`Sign in`

`Sign up`
```

但它们的行为逻辑不同。


## 1. Sign in / Sign up

这是：

# 页面跳转型功能

点击：

```
`→ Route Push`
```

进入独立页面：

- /signin

- /signup

因为：

登录注册属于：

# 流程型任务

需要：

- 表单

- 验证

- OAuth

- 状态管理

所以必须独立页面。


## 2. 齿轮按钮（Settings）

这里逻辑完全不同。

它不是：

```
`跳转页面`
```

而是：

# 局部 UI 控制器

点击后：

```
`打开侧边栏 Drawer`
```

例如：

```
`右侧 Slide Panel`
```

这是因为：

设置属于：

# 环境级控制（Environment Controls）

不是主流程。

所以：

- 不应该打断当前浏览

- 不应该离开当前页面

- 不应该发生 route change

因此：

## 最合理的是：

```
`Overlay / Drawer / Slide Panel`
```

而不是：

```
`/settings`
```


# 七、为什么这个设计高级

因为它没有采用：

- 传统 SaaS Navbar

- 强边框

- 大量按钮

- 多色彩强调

- 高信息密度

而是：

# “弱功能化”

即：

让 UI 看起来不像“工具”。

这是很多高端视觉网站的核心逻辑：

## 功能存在

但：

## 不让功能破坏氛围


# 八、这个 Hero 的核心设计哲学

可以总结为一句话：

# “让导航像世界入口，而不是菜单栏。”

因此：

- 字体偏展示性

- 留白巨大

- 状态切换极简

- Active 用存在感表达

- Inactive 用环境化处理

- Logo 不参与功能竞争

- 设置不跳页

- 登录注册独立流程

整个页面实际上是在构建：

# 数字展厅 / 音乐宇宙 / 艺术档案馆

式的空间感。
